How it works

From raw data to structured insights

The pipeline runs in two phases — setup and execution — both driven by language models with no manual configuration required.

1

Upload your dataset & instructions

Drag in a CSV (your list of entities) and a plain-English document describing what you want to find. That's the only input.

CSV Plain text
2

Agent auto-configures the pipeline

An LLM reads your instructions and generates the search templates, extraction fields, and prompts needed to run the pipeline — verified and auto-fixed before use.

DeepSeek / GPT Auto-verification
3

Web search & scraping

For each entity, the pipeline fires multiple targeted search queries, filters out irrelevant URLs, and scrapes full page content where useful.

Serper API BeautifulSoup URL filtering
4

Stored in a vector database

Every collected document is embedded and stored in a local vector database, indexed by entity. Nothing is thrown away.

Milvus Lite BGE embeddings COSINE similarity
5

RAG extraction — field by field

For each field to extract, the most semantically relevant chunks are retrieved from the vector database and passed to the LLM. The model returns structured JSON with confidence scores.

RAG Per-field retrieval Confidence scoring
6

VDB retry for missing fields

Low-confidence or missing fields trigger a second round of targeted vector database queries — no extra web searches needed.

VDB retry Focused LLM call

Core components

What's under the hood

Each component is independent and swappable. The pipeline is dataset-agnostic by design.

🤖

Agentic Setup

Reads your instructions and auto-generates the full pipeline configuration — search templates, extraction fields, and prompts. Includes a verification pass that catches and fixes common issues.

🔍

Search Layer

Fires multiple targeted queries per entity using Serper (primary) with Google CSE as fallback. Templates are auto-generated from your dataset schema with entity-specific placeholders.

🌐

Web Scraper

Fetches and cleans full page content from relevant URLs. Filters out PDFs, irrelevant domains, and low-quality pages before storing anything.

🗄️

Vector Database

Every collected document is embedded using BGE and stored in Milvus Lite — a local, file-based vector store. Indexed by entity so retrieval is always scoped to the right data.

✨

RAG Extraction

For each field, a semantic query retrieves the most relevant document chunks from the vector database. The LLM sees only the most relevant context — not a dump of everything collected.

📊

Evaluation

If ground truth is available in your dataset, extraction quality is automatically scored using F1 and Exact Match metrics. Confidence scores are included in every output.

Roadmap

What comes next

The core pipeline works end-to-end. These are the natural next improvements.

Accuracy

Verification layer

Cross-check extracted values against a second independent source before accepting them as final.

Coverage

Smarter retry loops

When a field is still missing after VDB retry, automatically generate new search queries targeting that specific gap.

Data quality

Scraping improvements

Better content extraction from complex page layouts, JavaScript-rendered pages, and structured data formats.

Scale

Batch processing

Run hundreds of entities in parallel with rate limiting, resumable sessions, and incremental output.

Flexibility

More data sources

Plug in additional search providers, academic databases, or domain-specific APIs alongside web search.

Evaluation

Richer metrics

Expand evaluation beyond F1/EM — semantic similarity scoring, field-level confidence calibration, and drift detection across runs.
